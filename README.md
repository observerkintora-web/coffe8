# ☕ Кофейная рулетка — Telegram Mini App + бот

Гость сканирует QR-код на столике → у него открывается мини-приложение
Telegram → он видит 3–6 чашек → нажимает на одну → случайно получает
приз («бесплатный сироп» или «бесплатный кофе») → бот присылает ему
уникальный код, который бариста активирует на кассе.

## Из чего состоит проект

```
coffee-roulette/
├── bot/                # Python-бот (aiogram 3)
│   ├── config.py
│   ├── db.py           # SQLite: коды призов + защита от повторной игры
│   ├── handlers.py     # /start, приём данных из мини-аппа, /check, /redeem
│   └── main.py
├── webapp/              # Mini App — то, что видит гость
│   ├── index.html
│   ├── style.css
│   └── script.js
├── qr/
│   └── generate_qr.py  # генерация QR-кода на мини-апп
├── requirements.txt
└── .env.example
```

## Шаг 1. Создать бота и Mini App в BotFather

1. В Telegram откройте **@BotFather** → `/newbot`, задайте имя и username
   (например `MyCoffeeBot`). Сохраните токен — он пойдёт в `BOT_TOKEN`.
2. Там же: `/newapp` → выберите вашего бота → задайте:
   - Title: «Кофейная рулетка»
   - Short name: например `roulette` (он понадобится для QR-ссылки)
   - Photo/GIF — превью мини-аппа (можно позже)
   - **Web App URL** — сюда позже впишете публичный https-адрес
     `webapp/index.html` (см. Шаг 2). Изменить его можно повторным
     `/newapp` → `/myapps` → `Edit Web App URL`.

## Шаг 2. Разместить папку `webapp/` где-нибудь с https

Telegram Mini App обязательно должен открываться по **https**. Проще
всего — статический хостинг, бесплатных вариантов несколько:

- **GitHub Pages**: закиньте содержимое `webapp/` в репозиторий,
  включите Pages в настройках репозитория.
- **Vercel / Netlify**: перетащите папку `webapp/` в веб-интерфейс
  (drag-and-drop деплой), получите готовый https-адрес.
- Свой сервер/VPS с Nginx и Let's Encrypt — тоже подойдёт.

Итоговый адрес будет вида `https://ваш-домен/index.html` — впишите его
в `WEBAPP_URL` в `.env` **и** в настройки Mini App в BotFather.

## Шаг 3. Настроить и запустить бота

```bash
cd coffee-roulette
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env
# откройте .env и впишите BOT_TOKEN, WEBAPP_URL, ADMIN_IDS

python -m bot.main
```

Бот держит соединение через long polling — для реальной кофейни его
удобно запускать на небольшом VPS через `systemd`/`pm2`/`screen`, чтобы
он работал постоянно.

## Шаг 4. Сгенерировать QR-код для столиков

```bash
python qr/generate_qr.py MyCoffeeBot roulette table_1.png
```

Это создаст QR, который сразу открывает Mini App (минуя экран бота).
Распечатайте и наклейте на столики/чек/стойку.

Если вместо этого хотите, чтобы QR вёл на самого бота (а кнопку
«Крутить рулетку» гость нажимал сам в чате), используйте просто
`https://t.me/MyCoffeeBot` — тогда сработает обработчик `/start`.

## Как это работает для бариста

1. Гость получает в чате с ботом сообщение с призом и 6-значным кодом
   (например `A3K7XZ`).
2. Бариста (чей Telegram ID добавлен в `ADMIN_IDS`) вводит боту:
   - `/check A3K7XZ` — посмотреть приз и статус, не списывая его;
   - `/redeem A3K7XZ` — отметить приз использованным.
3. Повторно тот же код `/redeem` не примет — вернёт «уже использован».

## Настройки, которые стоит подстроить под себя

- **Шансы призов** — в `webapp/script.js`, массив `PRIZES` (сейчас
  65% сироп / 35% кофе — сделал кофе более редким призом, поменяйте
  под свою экономику).
- **Число чашек** — там же, `MIN_CUPS` / `MAX_CUPS` (сейчас 3–6, как
  вы просили).
- **Ограничение «один раз в день»** — `PLAY_COOLDOWN_HOURS` в `.env`;
  поставьте `0`, если розыгрыш должен быть без ограничений.
- **Название заведения** в сообщениях бота — `SHOP_NAME` в `.env`.

## Важные примечания

- Токен бота никогда не публикуйте — держите его только в `.env`
  (файл уже не должен попадать в git).
- Мини-апп обязателен по https — локальный `file://` или обычный
  `http://` Telegram не откроет.
- Формально дизайн выигрышный для гостя в любом случае (проигрыша
  нет) — если захотите добавить вариант «повезёт в следующий раз»,
  просто добавьте третий элемент в массив `PRIZES` с ключом,
  например, `nothing`, и обработайте его в `PRIZE_LABELS` в
  `bot/handlers.py`.

## Обновление: одноразовые коды, редкость призов, админка (v3)

### Как теперь работает игра

1. Бариста после оплаты чека пишет боту `/newqr 150` (150 — сумма чека).
   Бот присылает одноразовый код и готовую ссылку `t.me/<bot>?startapp=КОД`.
2. Из этой ссылки сделайте QR (как раньше — любой онлайн-генератор) и
   отдайте гостю на чеке/стикере.
3. Гость сканирует → сразу открывается игра → выбирает карту → бот сам
   (не мини-апп!) определяет приз с учётом редкости и бюджета → присылает
   гостю приз и код для бариста.
4. Код одноразовый: повторное сканирование того же QR ничего не даст.

### Призы и бюджеты

Список призов, их редкость, себестоимость и месячные лимиты — в
`bot/prizes.py`. Правьте свободно под свою кофейню. `monthly_limit`
физически не даёт системе выдать больше N призов этого типа за
последние 30 дней — вместо этого гость получит обычный приз.

### Команды для персонала (нужен ваш Telegram ID в `ADMIN_IDS`)

- `/newqr СУММА` — создать одноразовый код на игру
- `/redeem КОД [СУММА_ЧЕКА]` — активировать приз гостя; сумму указывайте,
  если приз требует покупки (это и есть данные для отчёта о допвыручке)
- `/check КОД` — посмотреть статус приза
- `/stats [дни]` — сводка: сколько играли, что выпало, окупаемость

### Админка в виде Mini App (без отдельного хостинга)

Бот теперь сам поднимает небольшой веб-сервер (`bot/api.py`), который
отдаёт статистику ТОЛЬКО тем, чей Telegram ID в `ADMIN_IDS` — проверка
идёт по криптографической подписи Telegram (`bot/auth.py`), без паролей.

**Важно:** в отличие от игры, админку нельзя захостить статикой на
Vercel — ей нужен живой сервер. Это же заодно решает проблему «бот
работает только пока открыт PowerShell»: разверните `bot/` на
**Render.com** (бесплатный тариф для одного сервиса):

1. Зайдите на render.com → New → Web Service → подключите репозиторий
2. Start Command: `python -m bot.main`
3. Environment → добавьте те же переменные, что в `.env`
4. После деплоя Render даст адрес вида `https://coffe3.onrender.com`

Дальше в BotFather создайте второй мини-апп для админки (`/newapp` →
short name например `admin`) с Web App URL:
```
https://coffe3.onrender.com/admin/
```
Открывать эту ссылку должны только сотрудники — она физически отдаёт
403, если Telegram ID не в `ADMIN_IDS`, даже если кто-то узнает адрес.

### Известное упрощение (стоит знать)

Итоговый приз определяет бот (с учётом бюджета), а не сам мини-апп —
поэтому при выборе карты игрок видит нейтральное «🎁», а не конкретную
иконку приза: точный приз показывается только в сообщении от бота.
Технически можно сделать мгновенный показ приза прямо в мини-аппе, но
это требует API-запрос из мини-аппа к боту в реальном времени
(усложнение, отдельная задача, если понадобится плавность UX).
